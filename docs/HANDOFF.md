cold. `README.md` explains how to run the app and `docs/NOTES.md` records why

## What the app does

One speaking exercise a day. The user records up to a minute of audio answering
a prompt, and gets back a score with coaching. Three things were built out most
recently, and they're the bulk of the uncommitted diff:

**Accounts.** Firebase Auth with Google and email/password. Client SDK does the
sign-in, then posts the ID token to `app/api/auth/session/route.ts`, which mints
an httpOnly session cookie via the Admin SDK. Server components read that cookie
through `getCurrentUser()` in `lib/auth/server.ts`. `proxy.ts` at the repo root
guards `/results` and `/progress`.

**Streaks.** `lib/streaks.ts` is pure day-key arithmetic with no I/O, verified by
`scripts/check-streaks.mjs` (42 assertions, runs under `npm run check`).
`lib/users.ts` persists the result to `users/{uid}` in a Firestore transaction.

**Daily prompts.** Generated by an LLM the night before, stored in
`dailyPrompts`, deduped against recent prompts, falling back to the static
library in `lib/prompts.ts` when generation fails. Driven by
`app/api/cron/daily-prompt/route.ts`, scheduled in `vercel.json`, authenticated
with `CRON_SECRET`.

## Decisions that will look arbitrary unless you know why

These are the ones most likely to get "fixed" back into bugs.

**A "day" is a UTC calendar day, not the user's local day.** Streaks and prompt
rollover use the same `dayKey` (`YYYY-MM-DD`, UTC) so the two can never disagree
— a user cannot be shown today's prompt while their streak thinks it's still
yesterday. The cost is that a late-night session in a western timezone counts as
tomorrow. That's a deliberate trade; `docs/NOTES.md` has the longer version.

**Streak state is stored, not derived.** `users/{uid}` holds
`currentStreak`/`longestStreak` rather than recomputing from session history.
Recomputation would mean an unbounded read on every practice.

**The landing page must stay static.** This is the fragile one. Reading cookies
in a layout opts the whole subtree into dynamic rendering, so auth lives in
`app/(app)/layout.tsx` — a route group — and *not* in the root `app/layout.tsx`.
If you add a `cookies()` or `getCurrentUser()` call to the root layout, `/` goes
from `○` to `ƒ` and you won't get an error, just a slower landing page. Check the
route table in `npm run build` output: `/` should be `○ (Static)`.

**It's `proxy.ts`, not `middleware.ts`.** This Next.js version deprecated the
middleware filename. The exported function is `proxy`. Also note `AGENTS.md`:
this Next.js is newer than your training data, and the docs in
`node_modules/next/dist/docs/` are the authority.

**`NEXT_PUBLIC_FIREBASE_*` values are not secrets.** They're inlined into the
browser bundle by design and identify the project rather than authorize
anything; `firestore.rules` plus Auth is what protects data. Don't "fix" this by
un-prefixing them, which would only break the client. The genuine secrets are
`FIREBASE_PRIVATE_KEY`, `FIREBASE_CLIENT_EMAIL`, `OPENAI_API_KEY`, and
`CRON_SECRET`, all unprefixed and read only in server code.

**One logo composition, everywhere.** `components/brand/PoiseLogo.tsx` is a mic
grille set into the O of POISE. It was explicitly *not* paired with a separate
mic badge, since the embedded mic already says "voice" and two of them read as a
mistake. Call sites vary size through `className` only. The svg is sized to cap
height so it lands on the text baseline without magic offsets.

## Layout

Firebase lives behind two entry points, and which one you use matters:
`lib/firebase/client.ts` (browser, auth UI only) and `lib/firebase/admin.ts`
(server, privileged). All writes go through the Admin SDK — `firestore.rules`
denies client writes outright and allows only owner-scoped reads.

```
lib/auth/          session cookie, getCurrentUser, error mapping, safe redirects
lib/streaks.ts     pure day-key + streak arithmetic (no I/O — keep it that way)
lib/users.ts       users/{uid}, transactional streak update
lib/sessions.ts    practiceSessions repo; reads are owner-scoped by design
lib/dailyPrompts.ts LLM prompt generation, dedupe, static fallback
lib/openai.ts      transcription + analysis + prompt generation
proxy.ts           route protection (NOT middleware.ts)
app/(app)/         every authenticated route — keeps / static
components/brand/  PoiseLogo
```

## State of the environment

The code is done; the Firebase console side may not be. Verify before debugging
anything auth-shaped, because a missing provider looks like a code bug:

- Google and email/password providers enabled in Firebase Auth
- A web app registered, with its config in `.env.local` as `NEXT_PUBLIC_FIREBASE_*`
- `CRON_SECRET` set locally and in Vercel
- `firestore.rules` and `firestore.indexes.json` deployed (`firebase deploy --only firestore`)

`.env.example` lists every variable. `POISE_SCORING_MODE=mock` avoids spending
OpenAI credits while working on UI.

## Secrets

Audited clean. No credential has ever been committed — the only key-shaped
strings in the repo are the placeholders in `.env.example`. `.env.local` is
ignored and was never tracked.

`.gitignore` was since hardened from an exact filename list to globs, so
variants (`.env.staging.local`, `.env.backup`), service-account JSON under its
download name (`*-firebase-adminsdk-*.json`), and stray `.webm`/`.wav`
recordings are all caught. Since some of those patterns are broad wildcards over
`*.json`, there's a `!firestore.indexes.json` exception guarding the one config
that has to stay tracked. If you widen the JSON rules, re-run both checks:

```bash
git check-ignore -v .env.local serviceAccount.json recording.webm
git check-ignore -v .env.example firestore.indexes.json   # must print nothing
```

Two things not to change. The fourth commit uses `git add -A` on purpose: it
contains the route moves into `app/(app)/` alongside the `lib/demo.ts` and
`lib/sessionStore.ts` deletions, and staging both sides together is what makes
git record renames instead of delete-plus-add. And the parenthesized paths are
quoted so zsh doesn't glob them.

Then `git status && git log --oneline -8` and `git push -u origin main`
(`origin` is `github.com/anair34/poise.git`).

## Loose ends

- `components/brand/PoiseMark.tsx` is dead — nothing imports it. It survived
  only because several agents were editing that directory concurrently and
  deleting it risked a conflict. Delete it before the logo commit.
- `npm run check` warns `MODULE_TYPELESS_PACKAGE_JSON` from the `.mjs` scripts.
  Cosmetic; fixable with `"type": "module"` in `package.json`, which has other
  consequences worth thinking through first.
- The recorder's sign-in gate holds the recorded blob in memory while the user
  signs in with Google. A full page redirect loses it, which is why the gate
  uses a popup and offers "discard and record again" rather than linking out to
  the email sign-in page.
